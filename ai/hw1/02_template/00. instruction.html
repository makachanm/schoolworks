4. 구현 대상 및 실험 유의사항

구현 대상 알고리즘
  1. DFS: 가장 깊은 노드부터 탐색하며, 최적 해를 보장하지 않습니다.
  2. BFS: 가장 얕은 노드부터 탐색하며, 동일 비용 조건에서 최단 경로를 보장합니다.
  3. UCS: 누적 비용이 가장 낮은 노드부터 탐색합니다.
  4. A*: 경로 비용과 휴리스틱을 함께 고려하여 탐색합니다.
권장 비교 대상
  • BFS
  • UCS
  • A*
주의해서 다룰 알고리즘
  • DFS: goal을 찾더라도 긴 경로를 반환할 수 있음
  • Random Search: 결과와 실행 시간이 불안정함
구현 시 유의할 점
  • Graph search 방식으로 구현해야합니다.
  • 이미 방문한 상태를 불필요하게 반복 탐색하지 않아야합니다.
  • 반환값은 goal state에 도달하기 위한 action 리스트여야합니다.
  • 가능한 action은 up, down, left, right입니다.

8. 필수 수행 과제

Task 1. 핵심 파일 역할 설명
목표: 어떤 파일을 왜 쓰는지 스스로 설명할 수 있어야합니다.
  1. search.py, eightpuzzle.py, main.py, main_ui.py를 모두 열어 핵심 함수/클래스를 확인해야합니다.
  2. 각 파일을 역할 1문장 + 과제에서의 사용 시점 1문장으로 정리해야합니다.
  3. 보고서에 search.py는 구현 대상, 나머지 파일은 분석 대상임을 구분해 작성해야합니다.
보고서 필수 포함: 파일별 역할표(최소 4행), 본인 구현 중심 파일 명시.
Task 2. 알고리즘 동작 검증
목표: DFS/BFS/UCS/A*가 실제로 goal까지 가는지 확인해야합니다.
  1. 서로 다른 퍼즐 최소 3개를 준비해야합니다(쉬움/중간/어려움 권장).
  2. 각 퍼즐에 대해 DFS/BFS/UCS/A*를 모두 실행해야합니다.
  3. 각 실행마다 성공 여부, 경로 길이, 에러 발생 여부를 기록해야합니다.
  4. 실패가 있으면 실패 입력, 원인, 수정 후 재실행 결과를 함께 남깁니다.
보고서 필수 포함: 검증 로그 표(퍼즐 ID, 알고리즘, 성공/실패, 비고).
Task 3. 실행 시간 비교
목표: BFS/UCS/A*의 시간 성능을 공정하게 비교해야합니다.
  1. 동일 퍼즐 집합 최소 5개를 확정하고, 알고리즘별로 같은 순서로 실행해야합니다.
  2. 실행 시간은 초(second) 단위로 기록하고, 가능하면 소수점 3자리까지 표기해야합니다.
  3. 각 알고리즘별 평균 시간(Mean)과 최대 시간(Max)을 계산해야합니다.
  4. 시간 비교 표 1개 + 막대그래프 1개를 작성해야합니다.
감점 방지: 서로 다른 퍼즐로 알고리즘을 비교하면 공정 비교로 인정되지 않습니다.
Task 4. 경로 길이 비교
목표: 어떤 알고리즘이 더 짧은 해를 찾는지 분석해야합니다.
  1. Task 3와 동일 퍼즐을 사용해 알고리즘별 경로 길이(액션 개수)를 기록해야합니다.
  2. 퍼즐별 최소 경로 길이를 찾고, 각 알고리즘이 그 값과 얼마나 차이 나는지 비교해야합니다.
  3. “빠르지만 경로가 길다/느리지만 경로가 짧다” 같은 trade-off를 서술해야합니다.
보고서 필수 포함: 퍼즐별 경로 길이 표 + 핵심 해석 3문장 이상.
Task 5. A*와 휴리스틱 분석
목표: 왜 A*가 빠를 수 있는지 휴리스틱 관점에서 설명해야합니다.
  1. heuristic()가 무엇을 계산하는지 수식/설명으로 명시해야합니다.
  2. 예시 상태 2개 이상에서 heuristic 값 계산 결과를 직접 보여줍니다.
  3. A*의 우선순위가 g(n)+h(n)으로 결정됨을 설명하고, 실행 결과와 연결해야합니다.
  4. 휴리스틱이 부정확하면 어떤 문제가 생길 수 있는지 짧게 정리해야합니다.
보고서 필수 포함: 휴리스틱 계산 예시, A* 성능 해석, 한계 1가지 이상.
Task 6. DFS 한계 분석
목표: DFS가 왜 비교 기준으로 부적합할 수 있는지 근거로 설명해야합니다.
  1. DFS가 비효율적이었던 퍼즐 사례를 최소 1개 선택해야합니다.
  2. 동일 퍼즐에서 BFS/UCS/A* 결과와 나란히 비교해야합니다.
  3. DFS가 긴 경로를 만들거나 오래 걸린 원인을 탐색 순서 관점에서 설명해야합니다.
보고서 필수 포함: DFS 문제 사례(수치 포함) + 원인 분석 문장.
Task 7. 공정한 실험 설계
목표: 재현 가능한 실험 프로토콜을 제시해야합니다.
  1. 동일 입력 퍼즐, 동일 실행 환경, 동일 종료 조건을 명시해야합니다.
  2. 측정 항목(시간, 경로 길이, 성공 여부)과 측정 방법을 먼저 고정해야합니다.
  3. 실험 절차를 순서도로 쓰거나 1~2~3 단계로 기술해야합니다.
  4. 재실행했을 때 결과가 얼마나 유사한지 간단히 점검해야합니다.
보고서 필수 포함: 실험 조건 표, 절차 설명, 재현성 관련 코멘트.
Task 8. 난이도-성능 관계
목표: 문제 난이도가 성능에 미치는 영향을 설명해야합니다.
  1. 난이도 기준을 직접 정의해야합니다(예: 섞인 횟수, 목표까지 추정 거리).
  2. 쉬움/중간/어려움 그룹으로 퍼즐을 분류해야합니다.
  3. 그룹별 평균 시간과 평균 경로 길이를 계산해야합니다.
  4. 난이도 증가에 따라 어떤 알고리즘이 급격히 느려지는지 분석해야합니다.
보고서 필수 포함: 난이도 정의, 그룹별 통계표, 핵심 인사이트.
Task 9. 4x4, 5x5 확장 분석
목표: 8-puzzle 코드를 일반 N-puzzle로 확장할 때의 핵심 변경점을 정리해야합니다.
  1. 상태 표현(리스트 크기, 인덱스 계산, 목표 상태 생성) 일반화 방향을 작성해야합니다.
  2. search.py 내부에서 가능한 action 처리와 successor 탐색 로직을 어떻게 일반화할지 정리해야합니다.
  3. goal 상태 판정이 일반화될 때 탐색 로직이 어떤 영향을 받는지 설명해야합니다.
  4. 휴리스틱(Manhattan distance) 계산을 N 크기에 맞게 일반화하는 방법을 설명해야합니다.
  5. 메모리/시간 복잡도가 왜 급격히 증가하는지 원인과 대응 아이디어를 제시해야합니다.
보고서 필수 포함: 코드 변경이 아닌 설계안(개념), 예상 병목, 개선 방향 2가지 이상.
