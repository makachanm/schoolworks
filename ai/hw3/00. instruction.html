과제 4: 고양이가 있는 스마트홈 로봇청소기 MDP 구현

본 과제는 Markov Decision Process (MDP)의 핵심 구성 요소인 상태 공간, 전이 확률, 보상 함수, 종료 조건을 직접 정의하고, 이를 바탕으로 Value Iteration과 Policy Iteration을 구현해 최적 정책을 계산하는 실습입니다. 학생은 제공된 시뮬레이터를 수정하는 것이 아니라, tasks/ 내부의 task 파일을 순차적으로 완성하는 방식으로 과제를 수행합니다.

1. 과제 개요

이번 과제에서는 로봇청소기가 확률적인 격자 환경에서 어떻게 행동해야 하는지를 MDP로 모델링합니다. 단순히 코드를 완성하는 것이 아니라, 어떤 상태가 필요한지, 이동이 왜 확률적이어야 하는지, 보상을 어떻게 설계해야 바람직한 행동이 유도되는지를 함께 고민하는 것이 핵심입니다.

과제는 총 9개의 task로 나뉘며, 앞의 4개 task에서 MDP의 기본 요소를 정의하고, 이후 Value Iteration과 Policy Iteration으로 최적 정책을 계산하는 순서로 진행됩니다.

2. 고양이와 영향권 규칙

이번 과제에서 고양이는 단순한 배경 장식이 아니라, 로봇의 정책을 어렵게 만드는 핵심 확률 요소입니다. 맵에서 K 로 표시되는 칸은 고양이 중심 칸이며, 그 주변 상하좌우 1칸까지를 고양이 영향권으로 봅니다.

  • 고양이 중심 칸은 사실상 장애물처럼 취급됩니다. 로봇은 그 칸으로 안정적으로 들어가는 것이 아니라, 부딪히거나 밀려나거나 제자리에 멈출 수 있습니다.
  • 고양이 영향권에서는 이동이 불안정해집니다. 의도한 방향으로 갈 확률이 낮아지고, 제자리 유지 또는 주변 칸으로 밀려나는 경우가 생깁니다.
  • 특히 고양이 중심에 매우 가까운 위치일수록 간섭이 더 강합니다. 즉, 중심 칸과 주변 칸은 같은 위험 구역이 아니라 간섭 강도가 다른 두 단계의 확률 구역으로 이해하면 됩니다.
  • 먼지는 고양이 주변에 다시 생길 수 있습니다. 이 과제에서는 고양이 영향권에 있는 먼지 위치에 대해 재오염 확률이 추가되므로, 한 번 청소했다고 해서 항상 영구적으로 깨끗해지는 것은 아닙니다.
학생이 특히 주의할 점
Task 3에서는 이동 확률과 재오염 확률을 한꺼번에 섞어 생각하면 구현이 꼬이기 쉽습니다. 먼저 이동 / 청소 / 충전의 기본 결과를 만들고, 그 다음에 필요한 경우 재오염 확률을 별도로 결합하는 순서로 구현하는 것이 안전합니다.

또한 이번 과제의 고양이는 움직이지 않는 고정 장애물입니다. 만약 고양이의 좌표까지 매 턴 바뀌게 만들면 상태 공간이 급격히 커져서, 지금과 같은 tabular Value Iteration이나 Policy Iteration으로 다루기 훨씬 어려워집니다. 즉, 고양이는 강화학습에서 말하는 상태 공간 폭발을 설명하기 위한 교육용 장치이기도 합니다.

6. 권장 수행 순서

단계 1. MDP 모델링 먼저 완성

  • Task 1: 상태 공간 생성
  • Task 2: 종료 조건 정의
  • Task 3: 전이 확률 구현
  • Task 4: 보상 함수 구현

이 단계가 끝나야 Bellman update에 필요한 S, T, R이 모두 준비됩니다.

단계 2. Value Iteration으로 정책 계산

  • Task 5: Value Iteration
  • Task 6: Policy Extraction

이 단계가 끝나면 main_cli.py 와 main_web.py 에서 정책 기반 시뮬레이션이 가능해집니다.

단계 3. Policy Iteration까지 확장

  • Task 7: Q-value 계산
  • Task 8: Policy Evaluation
  • Task 9: Policy Iteration

최종적으로 tools/test_planners.py 를 통해 Value Iteration과 Policy Iteration 결과를 비교할 수 있습니다.

7. Task별 구현 내용

Task 파일 핵심 구현 내용
1 task1_states.py (x, y, dirt_mask, battery) 형태의 모든 유효 상태 생성

6 task6_policy_extraction.py 최종 가치 함수로부터 최적 행동 추출

9. 구현 시 주의사항

  • 상태 공간에서 벽 좌표는 포함하지 마십시오.
  • CHARGE 행동은 충전소에서만 유효해야 합니다.
  • 청소 성공 시 배터리 소모량과 이동 시 배터리 소모량 차이를 코드 흐름에서 확인하십시오.
  • 확률적 이동과 재오염은 서로 다른 단계의 확률 분기입니다.
  • terminal state에서는 가능한 행동과 정책이 자연스럽게 비어야 합니다.
참고
이번 과제의 핵심은 단순한 문법 구현이 아니라, 왜 이 상태 표현이 필요한지, 왜 이 보상 설계가 합리적인지, 어떤 정책이 실제로 유도되는지를 함께 해석하는 데 있습니다.

10. 생성형 AI 활용 원칙

본 강의는 생성형 AI 도구의 사용을 무조건적으로 금지하지는 않으나, 책임감 있는 사용과 철저한 검증을 엄격히 요구합니다. 이번 과제는 MDP 모델링과 Dynamic Programming의 핵심 논리를 스스로 이해했는지 평가하기 위한 것이므로, 단순 복붙 형태의 사용은 권장되지 않습니다.

  • ChatGPT, Claude, Copilot 등 생성형 AI를 사용했다면 어떤 task 또는 어떤 함수 수준에서 도움을 받았는지 반드시 기록하십시오.
  • AI가 제안한 상태 표현, 전이 식, 보상 로직, Bellman update 코드를 사용했다면 본인이 그 이유와 동작을 직접 설명할 수 있어야 합니다.
  • AI가 작성한 코드를 그대로 제출한 뒤 해당 로직을 설명하지 못하는 경우, 코드 리뷰나 구두 확인에서 큰 감점 또는 부정행위로 간주될 수 있습니다.
  • AI는 디버깅 보조, 개념 요약, 반례 점검, 의사코드 정리에 활용하고, 최종 구현과 검증은 반드시 본인이 수행하십시오.
  • 생성형 AI를 전혀 사용하지 않았다면 사용 내역에 "해당 없음"으로 명시하십시오.
권장 기재 방식
보고서나 제출 메모 마지막에 예를 들어 Task 5 수렴 조건 점검에 ChatGPT 사용, 최종 코드는 직접 수정 및 검증 완료 와 같이 짧게 남기면 됩니다.
